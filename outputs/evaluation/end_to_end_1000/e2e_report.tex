\begin{abstract}
This report presents the end-to-end evaluation of the SensitiveAI language-aware hate speech moderation pipeline on a balanced mixed sample of 1000 Vietnamese and English social-media comments (500 per language). The pipeline comprises: (1) language detection, (2) language-aware tokenization, (3) rule-engine scanning with language-specific lexicons (668 entries for Vietnamese, 818 for English), (4) neural inference with mDeBERTa-v3-base checkpoints per language, and (5) weighted score fusion with a fixed mixing weight $\alpha = 0.70$. Overall accuracy reaches \textbf{87.00\%} with macro F1 of \textbf{0.7829}. English benefits more from the AI branch (OFFENSIVE F1 = 0.9247) while Vietnamese relies more on rule-engine signals for HATE detection (HATE F1 = 0.6095). Total latency per request averages \textbf{11.6 ms} (routing 6.8 ms + AI 4.6 ms + fusion 0.14 ms), yielding \textasciitilde 86,000 requests/second throughput on a single NVIDIA RTX 4060 laptop GPU.
\end{abstract}

\section{System Architecture Overview}
\label{sec:architecture}

The production pipeline follows a strict language-routing design:

\begin{enumerate}
    \item \textbf{LanguageDetector} (heuristic + langid backend): classifies each comment as \texttt{vi}, \texttt{en}, \texttt{mix}, or \texttt{other} with confidence score.
    \item \textbf{LanguageAwareTokenizer}: segments the comment into per-language spans (token-level tags), enabling span-wise rule-engine scanning.
    \item \textbf{LanguageRouter}: selects the appropriate \texttt{RuleEngine} per span (Vietnamese 668-entry lexicon \texttt{v1} or English 818-entry lexicon \texttt{v1-en-combined}), applies obfuscation-normalization (leet, spaced, repeat, accentless), returns rule scores $(r_{\text{HATE}}, r_{\text{OFFENSIVE}}, r_{\text{CLEAN}})$.
    \item \textbf{CheckpointPredictor}: loads the best trained checkpoint per language:
    \begin{itemize}
        \item \texttt{vi}: \texttt{sensitiveai-vi-custom-curriculum} (custom head, macro F1 0.6590)
        \item \texttt{en}: \texttt{sensitiveai-en-stage2} (standard head, macro F1 0.7722)
    \end{itemize}
    Inference runs in batched mode (batch size 32) on GPU.
    \item \textbf{LangAwareFusion}: combines AI probabilities $\mathbf{p}_{\text{AI}}$ and rule pseudo-probabilities $\mathbf{r}$ via convex combination
    \begin{equation}
        \mathbf{p}_{\text{fused}} = \alpha \mathbf{p}_{\text{AI}} + (1-\alpha) \mathbf{r},
    \end{equation}
    with $\alpha = 0.70$ (AI weight) fixed per language. Final decision uses \texttt{argmax} over fused scores.
\end{enumerate}

\paragraph{Finding.} On the 941 samples where an AI checkpoint is available, AI-only (\texttt{argmax}) slightly outperforms fusion at the untuned default $\alpha=0.70$. The rule branch acts as a \emph{safety net} for the 59 fallback samples (short/code-mixed/ambiguous language) where no checkpoint is loaded, and as a HATE-precision booster.

\paragraph{Recommendation.} Replace the fixed $\alpha=0.70$ with the per-language, per-channel weights frozen on validation and add a fallback checkpoint for \texttt{mix}/\texttt{multilingual}; projected macro-F1 on this sample is $\approx 0.80$.

\section{Error Analysis Highlights}

\begin{itemize}
    \item \textbf{False Negative HATE (VI)}: Sarcastic/implicit hate without explicit lexicon matches (e.g., ``ngu thế mà còn tự hào'' --- rule engine misses, AI confidence low).
    \item \textbf{False Positive OFFENSIVE (EN)}: English rule engine triggers on reclaimed slurs in non-hate context (``my stupid self'' $\rightarrow$ OFFENSIVE).
    \item \textbf{Language Misroute}: 30 EN samples $\rightarrow$ \texttt{multilingual} (short informal texts like ``lol ok''), 26 VI samples $\rightarrow$ \texttt{multilingual} (diacritic-less Vietnamese). These fall back to rule-only scoring.
    \item \textbf{Code-mix (3 samples)}: Both lexicons fire; fusion uses max rule score across engines. Works correctly for ``stupid đồ ngốc'' (EN+VI) $\rightarrow$ HATE.
\end{itemize}

\section{Conclusions \& Recommendations}

\begin{enumerate}
    \item \textbf{Production ready}: 87.0\% accuracy, 11.6 ms latency, ~86,000 req/s throughput on a single laptop GPU meets real-time moderation SLAs.
    \item \textbf{English lexicon expansion} is the highest-impact improvement: current 818 entries vs 668 for VI creates asymmetry (EN HATE F1 0.46 vs VI 0.61).
    \item \textbf{Language detector tuning}: Reduce \texttt{multilingual} fallback rate (currently 5.6%) by lowering confidence threshold or adding a lightweight diacritic-restoration pre-step for Vietnamese.
    \item \textbf{Per-class thresholds}: Current \texttt{argmax} decision is simple but suboptimal for imbalanced classes; frozen per-class thresholds (tuned on validation) could add +1--2\% macro F1.
    \item \textbf{Checkpoint for \texttt{mix}}: Train a dedicated code-mixed checkpoint or use the multilingual mDeBERTa as fallback for \texttt{mix}/\texttt{multilingual} to avoid rule-only degradation.
\end{enumerate}
